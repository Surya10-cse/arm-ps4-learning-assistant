# Storage and contracts — schema v2 / API v1

Room file `adapt-v1.db` retains its installed filename, now schema version 2, single local learner. `MIGRATION_1_2` adds experience and goal-context fields with safe defaults while preserving all evidence. Backup is disabled. No destructive migration fallback. Versions 1 and 2 are committed; migration is validated on the actual Android phone.

`data/schemas/ai.adapt.data.AdaptDatabase/2.json` is generated by KSP and documents exact SQL, indices and foreign keys. Curriculum v2 seeds 64 curated questions; original IDs and scoring meanings remain intact. Scoring uses the bundled curriculum, not AI output or user-modified database content. `submission/catalogue.v2.json` exports the exact compiled graph, lessons and question bank.

## Module interfaces

`core.CONTRACT_VERSION = 1` remains the base learning-envelope contract. Legacy envelopes are in `schemas/learning.v1.schema.json`; the extended profile shape has its own `schemas/profile.v2.schema.json`. Production in-process calls use immutable Kotlin types rather than serialization; the v2 profile adds fields with migration defaults for legacy records. Domain validation additionally checks graph membership, score bounds, option membership, correct <= attempts, session identity and expected question. Schemas alone cannot enforce these relational invariants. Tutor response, model manifest and benchmark export retain independent version-1 contracts.

- `LearningRepository.saveProfile(name, goal, minutes)`: validates preference bounds, ends active assessment if preferences change, regenerates roadmap.
- `startAssessment(focus?)`: resumes an unfinished assessment with matching focus. Different focus ends the previous session. General diagnostic caps at 8, focused practice at 4 questions.
- `submit(item, selected)`: reselects authoritative expected question, checks selection, stores answer and deterministic updates atomically. Repeated/stale submission is rejected with no additional evidence.
- `continueAssessment(session)`: checks the authoritative active session before selecting a question or completing it; stale callers cannot resurrect an ended session. `resumeAssessment()` restores unfinished work after reopening.
- `LocalTutor.generate(prompt): Flow<TutorEvent>`: streams native text and a final measurement event. No scoring or roadmap write methods are exposed to inference.
- `ModelStore.importBundle(uri, checkActive, verifyRuntime)`: bounded ZIP extraction, exact filenames, duplicate/path rejection, strict manifest types/size/SHA checks and required runtime validation before atomic pointer commit. Existing active pointer survives validation failure. Startup recovers uncommitted staging directories.

Model JSON is defined by `schemas/model-manifest.v1.schema.json`. Import verifies paired artifacts but SHA-256 is integrity, not proof of publisher identity or semantic correctness. Only import locally exported/trusted bundles. A successful hash check is not proof the model will execute; native load/generation must pass on the phone.

Teaching JSON follows `schemas/tutor-response.v1.schema.json`; strict parsing rejects duplicate keys, extensions, wrong types, missing/extra fields, broken Unicode and trailing data. Structured streams are private until validation; invalid raw output is discarded and only a safe status message is persisted. There is no generated-question scoring path. The UI shows the newest 100 conversation entries; prompts use at most two short recent messages, selected skill, evidence/misconceptions, learner experience and goal context. Optional context is budgeted by UTF-8 bytes without splitting code points. Limit: 1600 prompt bytes and 2048 total native sequence tokens. Native stop is requested after 6000 emitted UTF-16 code units or two minutes; this is not an exact new-token cap. The release API's config overload ignores maxNewTokens, so the direct native sequence overload is used.

## Deterministic policy

For prior p, guess g=1/number-of-options, slip s=0.10, correct-response learning transition t=0.08:

```
correct: posterior = p(1-s) / [p(1-s) + (1-p)g]
wrong:   posterior = ps / [ps + (1-p)(1-g)]
correct next = clamp(posterior + (1-posterior)t, 0, 0.99)
wrong next = clamp(min(p, posterior), 0, 0.99)
```

An error cannot increase mastery. Prerequisites require probability >=0.70 for new learning; due recall remains available after a prerequisite declines. Learning targets <0.85. Roadmap priority weights gap 0.5, goal relevance 0.3, difficulty fit 0.2, plus due-recall bonus 0.3. Short budgets allocate a real study segment, so a valid 5-minute budget is actionable. Greedy packing is intentional, not a globally optimal scheduler. Assessment selection defers the most recent 16 exposed items, then balances coverage, uncertainty, relevance and difficulty fit with stable ID ties. Explicit focused practice can explore any catalogued skill regardless of goal. Options shuffle reproducibly per session while preserving canonical scoring indices. Eight items per competency still permit memorisation; there is no psychometric-validity claim.

Revision: wrong recall resets streak and interval to one day; successful due recalls use 1 day, 3 days, then previous interval × bounded ease up to 90 days. Correct practice before the due time retains the existing schedule so multiple questions in a single sitting cannot artificially stretch the interval. Ease is bounded [1.3,2.8]. Assessment counts are evidence, not engagement time. Completing a lesson or chatting never increases mastery.
